## Sensitivity questions before autodiff

Adjoint and tangent linear models have a long history in our field: operational 4D-Var at forecast centers {cite}`talagrand1987variational`, adjoint sensitivity studies {cite}`errico1997adjoint`, and ocean state estimation with adjoints generated by source-to-source transformation tools. Building and maintaining these adjoints took person-decades of specialized effort — which is precisely why so few models have them.

## Automatic differentiation in one page

The chain rule, applied mechanically to every elementary operation in your code {cite}`baydin2018automatic,griewank2008evaluating`. Not symbolic differentiation, not finite differences — exact derivatives of the program you actually wrote, at roughly constant-factor cost.

## Forward mode is the TLM; reverse mode is the adjoint

| | Forward mode (`jvp`) | Reverse mode (`vjp`, `grad`) |
|---|---|---|
| Climate-community name | Tangent linear model | Adjoint model |
| Propagates | Perturbations forward | Sensitivities backward |
| Cheap when | Few inputs, many outputs | Many inputs, few outputs |
| Typical use | Perturbation growth | Sensitivity of a scalar diagnostic to *everything* |

## What changes when adjoints are free

Every model you write in a differentiable framework has an exact adjoint, always in sync with the model code. Sensitivity analysis, variational assimilation, and gradient-based calibration stop being specialist infrastructure projects and become one-liners.

## What doesn't change

The mathematics still bites: chaotic dynamics make long-window gradients meaningless, reverse mode has a memory cost, and thresholds in physics have no useful derivative. Those are the subject of Part 3 — this book would be dishonest without them. For a broader survey of differentiable programming in Earth system modeling, see {cite}`gelbrecht2023differentiable,shen2023differentiable`.
